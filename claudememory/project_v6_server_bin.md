`~/server-hosting/beta4/bin` = v6 server (generation modern, port 9093, name "Valikorlia Reborn v7"); `install/` stays GS1. Start it from `bin/` (it chdirs to `servers/default`); find my own process by cwd.

v6 GS2 weapons (sources also in `beta4/patches/v6-weapons/`): -Chat (Tab, bottom strip, wheel), -Menu F1, -Outfit F2 (grid browser), -Players F3, -Guild F4, TileDefs..7, -KeyProbe. `protectedweapons` gives them to everyone.
GS1 client NPC scripts: `client_rev6/tools/gs1_to_gs2.py` translates them offline into `servers/default/gs2cache/<fnv1a64>.gs2`; `Script.cpp` looks the key up from the ORIGINAL source (m_clientside is minified, so hashing it never matched).

**Before touching the server:** check `ps` for a `gdb ./gs2emu` parent (the user debugs crashes that way) and for who owns the process on 9093; a TERM sent to a gdb-run server just stops it at the (gdb) prompt and blocks the port. Then stage files (patches/v6-weapons/install.sh) instead of restarting. Always confirm the NEW process really listens (`ss` on its pid), `ss | grep 9093` also matches the old one.

**Pitfalls (each cost real time):**
- The server rewrites `weapons/` on shutdown: stop the server FIRST, then copy files, then start, or the old version overwrites yours.
- In v6 GS2 `temp.name` is the function's name, never use `name` as a variable.
- GuiShowImgCtrl only reads files already on disk (no download); trigger download with a tiny `showimg`.
- A GuiButtonCtrl with its own skin hides what is under it; only ~28 KB of client script per weapon.
- Windows: `clientrelative = true`, set `position` from screenwidth; unbraced `if` one-liners and nested for loops with `substring`/`pos` once made scripts die silently.
- ALWAYS check the weapon compiles after deploy: in the server log the "Script compiler output" block comes just BEFORE the name line of the weapon that failed. `return {};` (empty array literal) breaks the GS2 compiler: assign to a temp first. -Guilds must be named exactly that (the server replies to clientside,-Guilds); it uses the server's gr.guild trigger commands (ranks member/officer/leader).
- Frame rate: `adventure_setframetick(ms)` works (50 = 20 FPS default, 33, 16 = 60 FPS) but `adventure_getframetick()` reads 0, so Menu keeps the choice in client.fpsmode (a string). OpenGL is v6's default, DirectX 9 via `$pref::video::useopengl`.
- `#L` in GS1 text args = `level.name`.
- An unset GS2 variable EQUALS 0 (so `x != 0` is false for null): use strings "on"/"off" for flags.
- v6 audio is global: `$pref::audio::sfxvolume` (.wav), `midivolume`, `mp3volume`, `radiovolume` (0..100) and `reversestereo`; scripts read and write them directly, the game saves them in game_config.txt. `setmusicvolume` does little. -Menu F1 has Menu / Sound / Settings / Info pages built on this (generator: patches/v6-weapons/menu_gen.py).
- v6 client GS2 string methods (proved with on-screen diagnostics, Nov 2026): `str.lower()` returns 0; `str.starts(x)` is wrong for longer x (a name did not "start with" itself). Use `s.substring(0, p.length()) == p` (helper pre()/suf() in -Outfit). `substring(start,len)`, `==`, `tokenize(sep)`, `length()` work. -Outfit/-OutfitCmd/-OutfitData* are generated by beta4/patches/v6-weapons/outfit_gen.py (lowercase copies are baked into the data as `Name|name`).
