`~/Downloads/graal_reborn/GServer-Python` is a C++ GServer-v2 (gs2emu, branch beta4), not Python. Built with ninja in `build/` (vcpkg from beta4). It is the login-server prototype for Graal v6, port **9094** (user said the port is unused).

Config that matters in `bin/servers/default/config/serveroptions.txt`: `generation = modern`, **`serverside = true`** (no NPC server means no GS2 bytecode), **`upnp = false`** (gs2emu otherwise asks the router to open the port itself, found when a throwaway test did exactly that), `onlystaff = true`, listserver 91.99.73.49:9098. `-Serverlist` weapon + `WEAPON -Serverlist` in `(defaultaccount).txt` + `world/*.gupd` added.

Two upstream bugs patched in that copy only, uncommitted: `Weapon::getJoinedClassesList` (`pop_back` on empty string) and `Script::getClientByteCode` (`any_cast` on a `shared_ptr<any>`). Both crash modern-generation servers; the main beta4 server (newmain) is unaffected.

**Why:** v6 clients log in to a gs2emu "login server" that delivers weapon scripts and the server list. See `client_rev6/NOTES_KILDKODER.md` 7.5.
**How to apply:** test throwaway servers in a copy under `$CLAUDE_JOB_DIR/tmp` with another port, `upnp = false`, `localhost = true`, and never start the real 9094 server (it registers with the user's ListServer) without asking. Related: [[project_custom_graal_client]], [[reference_valikorlia_2017_backup]].

**Update 5 Nov 2026 evening:** v6 now shows the server list from `-Serverlist`. Root causes found with the packet dump (`bin/gs2emu-pktlog`, built with `-DPACKET_LOGGING=ON`; the dump contains login passwords): (1) weapons without joined classes were never announced (`PLO_NPCWEAPONADD` only sent inside `if (!classes.empty())`); (2) weapon bytecode contains newline bytes and must be sent raw (`sendRawPacket`). Both fixed in GServer-Python (branch login-server) and in beta4 source + `patches/modern-generasjon-krasj.patch`. beta4 `install/gs2emu` rebuilt (backup `gs2emu.before-modern-raw`). `echo()` and script errors DO show in the client's `game_console.log`. v6's start window (nickname, guest/member, account, password) is the client's own. Run servers from their own `bin`/`install` folder (they look for `servers/` in the cwd). A login server and the main server (both started detached by me, ports 9094 / 9093) may still be running: check `ps` before starting another, port clashes look like "Could not connect listening socket".
